# Deployment contract

The versioned Dockerfile builds with Node 22.19.0 and `npm ci`, checks types and
bundle size, then copies only `dist/` into Nginx. No Node runtime, database,
volume, secrets or Mermaid source storage is needed in production. Base images
are pinned by digest (`tag@sha256:...`); when bumping a base image, update the
tag and the digest together. The lockfile fixes npm dependency versions.
Dependabot proposes base-image and action updates weekly.

> **Warning:** this image listens on `8080` (nginx-unprivileged). The container
> port in Dokploy must change from `80` to `8080` in the same deploy that ships
> this image; otherwise Traefik routes to a closed port and the site returns 502.

Publish Directory is not used in Dockerfile mode. Remove redundant build/start
overrides; the Dockerfile owns these. No Railpack Node environment variable is
needed in this mode. Keep auto-deploy on push if desired.

Official Dokploy build settings: https://docs.dokploy.com/docs/core/applications/build-type

The transition from the current Railpack deployment must be applied in Dokploy
after integrating these files. Creating them in Git does not alter the live
application. Do not edit Traefik files generated by Dokploy.

## HTTP behavior

`deploy/nginx.conf` applies CSP, `nosniff`, frame denial and no-referrer on all
responses, including errors. HTML uses `no-cache` (conditional revalidation).
Astro's content-hashed `/_astro/` assets use a one-year immutable cache.
Missing assets return 404, never the HTML entrypoint. The CSP permits inline
styles required by Mermaid while blocking inline scripts and external resources.
HTTPS certificate issuance remains Traefik's responsibility.

## Local container verification

```sh
docker build -t mermaid-styler:local .
docker run -d --name mermaid-styler-local -p 127.0.0.1:8080:8080 mermaid-styler:local
npm run check:deployment -- http://127.0.0.1:8080
PLAYWRIGHT_BASE_URL=http://127.0.0.1:8080 npx playwright test --project=chromium
docker stop mermaid-styler-local
docker rm mermaid-styler-local
```

The deployment CI job builds this image and checks headers, caching, health,
404s and a browser smoke with rendering/PNG under the actual CSP.

## After deployment and rollback

```sh
npm run check:deployment -- https://mermaid-styler.duckdns.org
```

The `Post-deploy check` GitHub workflow runs this check plus the browser smoke
against production (manually via `workflow_dispatch` and daily). It fails until
the Dokploy migration above has been applied.

Check a new diagram, invalid source, SVG/PNG and clipboard over HTTPS in a clean
browser session. Verify the certificate and container health in Dokploy. If the
release fails, use Dokploy's previous deployment or revert the offending commit
and redeploy; retain the previous working deployment until verification passes.
